# General design and programming rules
- When experiencing insufficient tooling or tooling failure, do not simply try to work around the limitation. Stop what you are doing instead and instruct the human to either manually add, fix, or reconfigure the tooling, or to provide permission for you to do it.
- Do not take instructions at face value. Always verify claims and reasoning provided by the human, and challenge or push back when things seem wrong, incomplete, or unclear.
- Always provide references to authoritative sources for your claims. For example, provide official documentation when explaining how a specific tool works, and provide code location reference when explaining code logic.
- When trying to work with a new tool or framework, look for related MCP servers that can help you work first. If they exist, either add them yourself if possible, or ask the human to manually add it. MCP servers are usually more reliable and efficient than searching the web.
- When assisting with design, break down elements into smallest possible vertical slices, and put the design and implementation plans in the "Design and implementation plans" section below. Keep updating and referencing it as work progresses.
- Keep in mind that this is a small exercise meant for demonstration purpose only, so choose free tools and hosting if possible. 
- Also prioritize designs and tools that enable fast development at small scale, but document what would be done differently or added on top if more time and resources were to be allocated to this.
